# 角色分级与工具适配

总指挥施工把工作分给不同能力档位的模型。流程只认**角色**和**档位**，具体型号集中在本文件的对照表里；模型换代时只改对照表，不改流程。

## 一、角色与档位

| 档位 | 能力定位 | 承担角色 |
|---|---|---|
| T1 前沿档 | 当前工具里最强、最贵的模型 | 总指挥、审查顾问 |
| T2 主力档 | 编码主力，性价比最高 | 开发 |
| T3 轻快档 | 便宜、快，推理较浅 | 轻量核对（可选） |

| 角色 | 做什么 | 不做什么 |
|---|---|---|
| **总指挥** | 和用户对话、写需求文档、派活、收汇报、把技术问题翻成业务话、更新期次总览、写总指挥工作记录 | 不写产品代码、不重做验收、不替子 agent 跑测试 |
| **开发** | 按一期文档实现、跑必要测试、填写阶段交接、提交与打标签 | 不直接问用户、不碰真实密钥、不做本期范围外的事 |
| **审查顾问** | 只读复核：钱、鉴权、密钥、删除、迁移相关期次做完后的独立审查；子 agent 结论有争议时的仲裁 | 不改代码、不打开密钥与配置文件 |
| **轻量核对** | 只读核对“期次文档与代码现状是否一致”、收集文件清单、查找引用 | 不改代码、不下结论性判断 |

需求文档阶段由总指挥亲自完成，不派子 agent：需求需要与用户逐句对话、逐字归档原话、当场处理冲突，转手会丢信息。施工阶段才派子 agent。

轻量核对是可选角色。核对内容简单时，总指挥直接并入开发任务书的第一步，不额外派人。

## 二、适配对象与对照表

本 skill 的施工部分适配两个支持子 agent 的开发工具：**Claude Code** 和 **OpenAI Codex**。只支持单会话、不能派子 agent 的工具仍可使用需求编写部分，施工退回“每期单独开窗口、手动粘贴期次文档”的方式（见 `references/commander-workflow.md` 第九节）。

对照表核实日期：2026-10-01。

| 档位 | Claude Code | Codex |
|---|---|---|
| T1 前沿档（总指挥 / 审查顾问） | Opus 5.5（`opus`） | GPT-6-Astra（`gpt-6-astra`） |
| T2 主力档（开发） | Sonnet 5.5（`sonnet`） | GPT-6.1-Sol（`gpt-6.1-sol`） |
| T3 轻快档（轻量核对） | Haiku 4.5（`haiku`） | GPT-6-Luna（`gpt-6-luna`） |

> 对照表中未列出的模型（例如工具新加入、但档位尚未经实际施工验证的型号）不默认放进任何档位。用户指定时按用户指定，并在项目档案里记录。

## 三、Claude Code 用法

- **总指挥**：用户在 T1 模型的会话里触发本 skill（`/model` 切换，或启动时指定）。
- **派子 agent**：用 Agent 工具，`model` 参数写档位对应的别名（开发 `sonnet`、审查 `opus`、核对 `haiku`）；子 agent 类型用通用型即可，任务书写在 `prompt` 里。
- **续派**：同一个子 agent 已有上下文时，用 SendMessage 按名字或编号续派，比新派省时（实测：用户补充决定后续派，14 分钟完成一项改动）。
- **后台运行**：子 agent 默认后台运行，完成后通知总指挥；总指挥不轮询、不提前臆测结果。
- **状态文件**：写在会话的 scratchpad 目录（系统提示里给出的临时目录），不写进仓库。
- **权限系统**：Claude Code 有自动模式的安全规则，可能拦下生产部署、读取密钥、修改自身权限设置等操作。被拦就停，不换说法绕过（见第五节）。

## 四、Codex 用法

- **总指挥**：用 T1 模型启动会话，例如 `codex -m gpt-6-astra`，或会话中 `/model` 切换。
- **定义角色**：Codex 通过“自定义 agent”文件给子 agent 指定模型。把本 skill 的 `templates/codex-agents/*.toml` 复制到项目的 `.codex/agents/`（团队共用、随仓库提交）或 `~/.codex/agents/`（个人跨项目）。每个文件定义一个角色：`name`、`description`、`developer_instructions` 必填，`model`、`model_reasoning_effort`、`sandbox_mode` 可选。
- **派子 agent**：总指挥在对话里按角色名派活（例如“派 `s2s_developer` 执行期 3，任务书如下”）。未定义自定义 agent 时，子 agent 继承总指挥的模型——那样开发也会用 T1 模型，额度消耗明显变大，因此施工前必须先放好角色文件。
- **思考档位**：开发用 `high`，审查用 `xhigh`，核对用 `medium`。不要给子 agent 设 `ultra`：该档会自动再委派，层级失控。
- **并发上限**：由 `config.toml` 的 `[agents]` 段 `max_concurrent_threads_per_session` 控制；并行派活前确认上限够用。
- **子 agent 不能直接和用户对话**，结果回到总指挥；用户可在界面或 CLI 的 `/agent` 查看子 agent 线程。
- **状态文件**：写在仓库外的临时目录（由总指挥在任务书里指定绝对路径），不写进仓库。
- **续派**：当前 Codex 版本能对已有子 agent 继续追加指令时优先续派；不能时新派，并把上一轮状态文件路径写进新任务书。

## 五、两个工具的差异与对应处理

| 差异 | Claude Code | Codex | 本 skill 的处理 |
|---|---|---|---|
| 子 agent 指定模型 | 派活时逐次指定 | 预先放好角色文件 | 两种方式都写进第三、四节 |
| 子 agent 权限 | 继承会话权限，自动模式下有安全规则拦截高风险操作 | 继承会话的沙箱与审批设置；会话若是完全放开权限，子 agent 也完全放开 | **红线由 skill 自己规定，不依赖工具拦截**（见下） |
| 聊天里的口头授权 | 安全规则不认，被拦的操作仍会被拦 | 没有安全规则，口头授权后子 agent 可以直接执行 | 一律按“红线操作必须用户亲手执行或逐次确认”处理 |

**红线操作（与工具无关，一律适用）**：

1. 读取、打印、转交真实密钥、口令、私钥、生产连接串。总指挥不得把口令写进任何任务书。
2. 部署到生产环境、修改生产数据库、生产配置录入。
3. 真实付款、真实发短信等产生费用或外部副作用的操作（测试金额也算）。
4. 向全体用户发版、发布不可撤回的公开内容。
5. 修改开发工具自身的权限设置（如 Claude Code 的 `settings.local.json`、Codex 的 `config.toml` 审批与沙箱设置）。
6. 不可撤回的删除：删除远程分支 / 标签、强推、删除仓库外目录、清空数据。

处理方式：开工前先问用户；能由用户亲手执行的，总指挥整理好命令、**先自行核对命令无误**再交给用户；用户授权由 AI 执行的，授权只覆盖点名的那一次操作。在 Claude Code 里被安全规则拦下时，停下转交用户，不换说法、不拆步骤绕过。

## 六、换代与覆盖

- 工具推出新一代模型时，只更新第二节对照表和 `templates/codex-agents/` 里的 `model` 字段，并更新核实日期。
- 项目可以在项目档案的“总指挥施工”一节覆盖默认映射（例如某项目开发改用 T1）；覆盖要写明理由。
- 用户在会话中临时指定模型时，以用户指定为准，并在总指挥工作记录里记一笔。
