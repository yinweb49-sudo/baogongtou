# 全自动模式

包工头施工有两种运行模式：

| 模式 | 什么时候用 | 要用户拍板的事 |
|---|---|---|
| **半自动（默认）** | 用户在电脑前，随时能答复 | 按 `foreman-workflow.md` 第十节《待您决定》处理：卡住施工的弹窗问，不急的到期按默认 |
| **全自动** | 用户要长时间离开，希望 AI 把一长串期次做完 | 不打断用户、不停工：包工头按自己的建议直接定，全部记进《决策报告》；结束时交《决策报告》+《验收报告》 |

用户没说“全自动”时一律按半自动。全自动只改变“停下等用户”的环节，其余施工规则（任务书、测试纪律、Git 纪律、必审、相称原则、凭据红线）完全不变。

## 一、开启流程

用户说“全自动模式”“开全自动”“我要离开，你自己做完”等，包工头按顺序做三件事，三件都完成且用户回“确认开启”后才进入全自动。用户回复之前仍是半自动。

### 1. 自检（包工头亲自做，逐条出结果）

| # | 检查项 | 怎么查 | 不满足时 |
|---|---|---|---|
| 1 | **视觉已确认** | 期次总览的门槛线状态、原型期《前端确认记录》 | **不能开启**。告诉用户原因：视觉是整套开发的底座和方向，没经用户确认就自动做后端，用户回来对页面不满意时，全套开发都要返工。引导用户先用半自动把原型看完、确认，再开全自动。没有界面、门槛线已豁免的需求不受此条限制 |
| 2 | 文档完整 | 需求文档和剩余期次都已写完，状态明确 | 不能开启，先补文档 |
| 3 | 没有卡住施工的未答事项 | 《待您决定》里“卡住施工”的未答项 | 开启前一次问清（这时用户还在） |
| 4 | 剩余期次不需要用户提供材料 | 期次文档的“需用户提供”“先问用户的步骤” | 需要材料的期次标为跳过；剩余期次全部依赖它时不能开启 |
| 5 | 代码现场干净 | `git status`、陌生提交、保存策略 | 先按开工准备处理 |
| 6 | 环境能跑 | 派一个子 agent 真启动开发环境、跑一次相关测试 | 先修好环境 |
| 7 | 模型可用 | 按 `model-roles.md` | 先解决 |
| 8 | 额度用完能自动续上 | Claude Code：只读查看用户设置里 `autoContinueAtUsageLimit` 是否为 true | 写进注意事项：不开的话额度用完会一直停着；请用户开启，或用户明确同意后包工头代为写入 |
| 9 | 对话能自动压缩 | Claude Code：用户设置里 `autoCompactEnabled` 不是 false | 同上 |
| 10 | 电脑不会休眠 | Windows 用 `powercfg /query` 只读查看休眠时间；其他系统按实际 | 写进注意事项，请用户关掉休眠 |

第 8–10 条 Codex 下的对应设置未核实，按“请用户自行确认”写进注意事项。包工头只读这些设置，不擅自修改用户配置和权限。

### 2. 告知注意事项（固定内容，一次讲完）

```markdown
已开启包工头模式（当前阶段：包工头施工）。全自动开启前请您知悉：

自检结果：<逐条 ✅ / ❌，❌ 写原因和怎么补>

开启后：
1. 不再打断您。要拍板的事我按自己的建议直接定，每条都记进《决策报告》，写明理由、其他选项、推翻的代价和能回退到的版本。
2. 以下操作我不做，记为“等您回来执行”，先做不依赖它们的工作：花钱、正式上线给所有用户、删除数据、动共用服务器等不可撤回的操作。
3. 每个功能包做完，我派人按测试步骤自己走一遍、留证据，不等您试用。
4. 结束时给您推送通知，交《决策报告》和《验收报告》，并打开试用程序、给您测试步骤。
5. 您中途回来随时可以问进度；说“停”就停在安全位置；说“切回半自动”，未复核的自动决策会转成待您追认的事项。

需要您确认：
- 会话处于自动模式（否则会卡在权限确认弹窗上）
- 电脑不休眠、不断网
- <自检里需要您处理的项>

风险：自动决策是 AI 的判断，您回来若推翻关键决策，返工量可能比半自动大。

确认无误请回复“确认开启”。
```

### 3. 用户回“确认开启”

把运行模式写进期次总览 README 的“施工指挥基线”和当轮工作记录：`运行模式：全自动（YYYY-MM-DD HH:mm 开启）`，然后开工。

## 二、全自动下的替代规则

| 半自动下停下等用户的环节 | 全自动下的做法 |
|---|---|
| 《待您决定》的事项、子 agent 自加的规则 | 包工头当场按建议定，记进当前决策台账（状态“全自动决策，待用户复核”）和《决策报告》。不弹窗，不放“待您决定”区块 |
| 红线操作（第九节“先问用户”四类） | 不做。记进《验收报告》“等您回来执行”，依赖它的期次一并跳过，先做其他不依赖它的期次和功能包 |
| 大功能完工唤起试用、等反馈 | 不等。派一个子 agent（施工队档）按交付包试用说明逐步走一遍，有浏览器或截图工具就留截图，否则留启动日志和测试结果；走不通的按正常流程派修。包工头不亲自验收 |
| 必审期次 | 照常派监理；阻断项照常修完才算完成 |
| 拆分熔断 | 包工头按第十五节复盘后自动选简化方案，记进《决策报告》；同一交付包第二次熔断，就停止这个交付包，标“未完成”，转做其他不依赖它的功能包 |
| 轮次交接 | 不等用户开新窗口。照常约每 8–10 次派活把工作记录写进仓库并提交，然后继续；工具自动压缩对话后，第一件事是重读最近的工作记录、《决策报告》和期次总览，再接着派活 |
| 额度刹车线（用户给了额度要求时） | 照常守住，到线就收尾出报告 |
| 和用户沟通 | 不发过程动态，不发每期简报；只在开启、结束、异常停止时说话。用户中途回来问进度，按交付包进度表答复后继续 |

**一律不变的红线**：不碰凭据、不绕过工具拦截（被拦下就记进报告、跳过该步骤）、不擅自修改用户配置和权限、Git 安全纪律。

## 三、什么时候结束

出现任一情况就收尾：

- 剩余期次全部完成；
- 剩余期次全部依赖“等您回来执行”的操作或“未完成”的交付包；
- 额度刹车线到了；
- 用户说“停”；
- 环境整体坏掉、子 agent 连续派活都无法启动（不硬撑，留现场）。

收尾顺序：

1. 进行中的期次收到安全点，等子 agent 交回；
2. 写《决策报告》和《验收报告》（模板见第四节），连同工作记录一起提交；
3. 有可用的交付包时，按 `foreman-workflow.md` 第五节唤起试用程序；
4. Claude Code 下用推送通知工具（PushNotification）发一句，例如“包工头：全自动已结束，3 / 4 个功能包可用，有 2 项待您执行”；
5. 最后一条消息：交付包进度、最需要您复核的 3–5 个关键决策（按推翻代价从大到小）、等您执行的操作、测试步骤（按第五节试用说明格式）、两份报告的位置。

用户回来后默认回到半自动。用户推翻某个自动决策时，按 `foreman-workflow.md` 第六节“答复改变了已确认的决定”处理，从该决策记录的回退锚点开始评估返工范围。

## 四、报告模板

放在 `docs/<功能名称>/`，文件名带轮次和日期，用业务话写。

### 《全自动决策报告》

````markdown
# <功能名称> · 全自动决策报告（第 N 轮，YYYY-MM-DD HH:mm 至 HH:mm）

> 共 <n> 项自动决策。建议优先复核标“★”的项（推翻代价大）。

| 编号 | 期次 | 要决定的事 | 我选了 | 为什么 | 其他选项及后果 | 推翻的代价 | 回退锚点 |
|---|---|---|---|---|---|---|---|
| ★ AD-001 | 期 5 | <问题，业务话> | <选项> | <理由一两句> | <B：……> | <要改哪些、约几期> | `checkpoint/<slug>/phase-4` |
````

- 每项同时登记进当前决策台账，编号互相对应（`AD-xxx` ↔ `D-xxx`）。
- 子 agent 自加的规则、熔断后选的简化方案、跳过的红线操作，都算决策，全部列入。

### 《全自动验收报告》

````markdown
# <功能名称> · 全自动验收报告（第 N 轮）

## 一、结果
- 交付包：<a / b 已可用>
- 运行时长与派活次数：<……>
- 结束原因：<全部完成 / 剩余都依赖等您执行的操作 / 额度刹车线 / ……>

## 二、各交付包验收情况
| 交付包 | 用户能用上什么 | 状态 | 验收证据 | 已知限制 |
|---|---|---|---|---|
| <名称> | <一句话> | 可用 / 部分可用 / 未完成 | <截图路径 / 测试结果 / 启动日志位置> | <没做的极端情况> |

## 三、等您回来执行
| 操作 | 为什么没自动做 | 依赖它的期次 | 怎么执行（包工头可代办的写“说一声我来做”） |
|---|---|---|---|

## 四、未完成与异常
<熔断停止的交付包、被工具拦下的步骤、偶发失败的测试；没有写“无”>

## 五、请您试用
<按 foreman-workflow 第五节试用说明格式：测试步骤不超过 7 步，注意事项不超过 4 条>
````
