## 前端原型与视觉确认（有界面的项目必填）

从无到有且存在用户界面的需求，skill 会先写最小业务草案，再做一期「前端原型 + 模拟数据」交用户确认。**需求文档和全部期次一次写完**，只在期次序列上划一条视觉确认门槛线：原型期完成后唤起本地调试入口交用户实测，确认并复核后才施工后端。这里写清原型怎么跑、从哪个地址看、模拟数据放哪里，避免每次追问。

- 本地预览启动命令：例 `npm run dev` / `pnpm dev` / `docker compose up web`；纯后端项目填“无界面”
- 本地预览入口地址：例 `http://localhost:5173/xxx`；桌面端 / 移动端写实际打开方式（哪个调试包、怎么装、进哪个菜单）
- 预览前置条件：例 需先 `npm install`、需打开 mock 开关、需要测试账号；没有填“无”
- 模拟数据存放约定：例 `src/mocks/` 下按功能建目录，导出与真实接口同形状的数据；接后端时只替换数据来源，不改页面
- mock / 调试入口与生产隔离方式：例 `import.meta.env.DEV` + 依赖注入；生产构建测试必须确认无 mock 引用
- 前端组件与设计语言来源：例 组件库名 + 现有页面参考路径，原型必须沿用，不新造风格
- 原型允许触碰的范围：只做页面与交互；不建表、不写正式接口、不接鉴权、不做数据迁移
- 视觉确认结论记录位置：例 `docs/<功能名称>/开发提示词/期1-*.md` 的「前端确认记录」
- 视觉确认版本锚点：优先提交号；无 Git 时用不可覆盖的 `prototype-YYYYMMDD-HHmm-<短哈希>` + 文件清单 SHA-256 + 运行命令；同时记录页面入口和截图 / 录屏路径
- 技术探针约定：仅当数据、第三方、性能或安全事实会阻塞原型成立时设期 0；只产证据，不建设正式底座

## 总指挥施工（阶段二）

不填时按 skill 默认值执行，总指挥会在第一次汇报里说明用了哪些默认值。

- 开发工具：Claude Code / Codex / 两者都用（不同电脑）
- 角色模型覆盖：无（按 `references/model-roles.md` 系列对照）/ <角色 → 模型系列，及理由；只写系列名，不写版本号>
- Codex 角色文件位置：`.codex/agents/`（随仓库）/ `~/.codex/agents/`（个人）/ 不用 Codex
- 测试纪律：例 开发中只跑相关测试、收尾全量一次；界面调整阶段不跑自动测试，由用户自测
- 测试命令与日志参数：例 `dotnet test --logger trx` / `npm test -- <过滤参数>`
- 端口分配：例 用户走查 5080 / 子 agent 联调 5090 / 子 agent 自测 5095；无本地服务填“不涉及”
- 线上操作：默认由总指挥直接完成（部署、服务器配置、后台录入、复用已有配置），凭据用脚本读写不打印；例外写在这里，如“新服务商 API Key 由用户自己在后台填”
- 先问用户的操作：默认为不可撤回操作、花钱或有外部副作用的操作、动共用基础设施、不可撤回的删除；可追加
- 工具权限约定：例 已在全局规则里放行部署脚本，命令须单独一行原样执行；被拦时用户切确认模式点允许
- 必审范围：默认“涉及钱的期次必审”；可追加鉴权、删除、迁移
- 额度管理：无额度要求，不主动询问（默认）/ 本轮在 <额度窗口> 内完成，刹车线 <如 75% 或离重置不到 40 分钟>，按实测消耗收缩到完整功能环节
- 汇报对象的沟通约定：例 全程中文、业务语言、称呼 <称呼>
- 多台电脑的仓库路径：例 家里 `E:\work\app`、公司 `D:\code\app`；任务书统一写“以当前所在目录为准”
