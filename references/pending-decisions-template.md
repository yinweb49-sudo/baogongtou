# 《待您决定》模板

施工期间需要用户拍板的事，包工头统一记在 `docs/<功能名称>/待您决定.md`，不只留在聊天里。用法见 `foreman-workflow.md` 第十节“待您决定”。

写作要求：

- 每项一个固定编号 `Q-xxx`，全功能连续编号，不重用。
- 第一次提出时写完整：现状用具体例子讲清，选项写业务后果，给出建议和理由。之后每次再问都从这里**原样复制**，不重新概括。
- 用业务话写，不出现代码术语。
- 用户答复后，把原话记进需求证据（编号接续），本项移到“已决定”并写明落地位置。
- 包工头亲自维护；并行施工时子 agent 不写本文件，只在汇报里列出要用户决定的事，由包工头登记。

````markdown
# <功能名称> · 待您决定

> 包工头维护。向用户提问一律从本文件原样复制，不重新概括。

## 未答

- 现状（具体例子）：<现在是什么样，用一个具体场景讲清>
- 选项：
  - A：<做法> → <对用户 / 业务的后果>
  - B：<做法> → <对用户 / 业务的后果>
- 包工头建议：<A>，理由：<一两句>
- 最晚答复：立即（期 N 停在这里等）
- 到期未答：必须等答复，不按默认执行
````
