# 轻记 LightDiary · 项目档案（requirements-profile）

> **这是一份虚构的示例档案**，仅用于演示 `requirements-profile.md` 该怎么填。
> 里面的产品、服务名、端口、路径都是编造的，请勿照抄——按 `references/project-profile-template.md` 填你自己项目的真实值。
> 本例特意采用“桌面前端 + 本地后端 + 云端后端 + 双数据库 + 订阅计费”的较复杂形态，方便展示模板的完整结构；你的项目更简单就删掉用不上的层。

## 基本信息

- 项目名称：轻记 LightDiary（虚构·离线优先的桌面日记 / 手账应用）
- 仓库根说明文件：`README.md` + `docs/架构总览.md`
- 产品视角 / 沟通约定：面向重视隐私的个人用户，先讲“做完能干什么”，再讲实现
- 默认文档强度：标准；涉及账号、订阅、隐私数据迁移和批量删除时升级为审计

## 架构分层

| 占位符 | 本项目对应 | 说明 |
|---|---|---|
| `{{前端}}` | `desktop-web`（Electron + React） | 桌面客户端前端，dev 端口 5180 |
| `{{本地后端}}` | `local-api`（`RunMode=Offline`） | 本地 SQLite，端口 8790，负责离线读写与本地检索 |
| `{{云端后端}}` | `cloud-api`（`RunMode=Online`） | 云端 PostgreSQL，端口 8890，负责账号登录、会员订阅计费、云同步、AI 润色网关 |
| `{{运行档位机制}}` | `RunMode` 开关（Offline / Online） | 同一套后端代码，切数据库 / 服务注册 / 路由白名单 |

## 数据库

| 占位符 | 本项目对应 |
|---|---|
| `{{主库}}` | SQLite（客户端本地，离线档位） |

## 鉴权与白名单术语

- `{{鉴权方案}}`：`Bearer(User)`（登录用户）/ `Bearer(DeviceToken)`（本地设备令牌）
- `{{白名单机制}}`：`OfflineRouteFilter` / `OnlineRouteFilter`（按运行档位暴露路由；某接口在一个档位 404 属正常）
- 计费机制：会员订阅（按月 / 按年，云端结算）

## 前端原型与视觉确认

- 本地预览启动命令：`npm run dev:desktop`
- 本地预览入口地址：起 Electron 窗口后从左侧「日记」菜单进入对应页面；浏览器直连调试用 `http://localhost:5180/<路径>`。原型阶段本地后端 8790 不参与，页面直接读模拟数据
- 预览前置条件：首次需 `npm install`；无需登录态和测试账号
- 模拟数据存放约定：`desktop-web/src/mocks/<功能名>/` 下按页面导出数据，形状与后续真实接口返回一致；接后端时只把数据来源从 mock 换成 API 调用，页面组件不动
- mock / 调试入口与生产隔离方式：只在 `import.meta.env.DEV` 下注册 mock provider；生产构建测试检查产物无 `src/mocks` 引用和调试路由
- 前端组件与设计语言来源：沿用 `desktop-web/src/components/` 现有组件与 `docs/设计规范.md`；原型不引入新组件库、不新造视觉风格
- 原型允许触碰的范围：只做页面与交互；不建 SQLite 表、不写 `local-api` / `cloud-api` 接口、不接 `Bearer` 鉴权、不做迁移
- 视觉确认结论记录位置：`docs/<功能名称>/开发提示词/期1-*.md` 的「本地预览与用户确认」和「前端确认记录」
- 视觉确认版本锚点：优先提交号；无 Git 时用不可覆盖的 `prototype-YYYYMMDD-HHmm-<短哈希>` + 文件清单 SHA-256 + 运行命令；同时记录 Electron 页面入口和 `docs/<功能>/原型截图/` 下截图
- 技术探针约定：只有云端数据、AI 接口时延或权限会阻塞原型成立时设期 0；探针只产证据，不写正式业务服务

## Git 代码检查点与远程备份

- 默认保存策略：本地标签
- 已批准的目标远程：无，只有用户在当前任务明确要求时才升级为远程分支
- 分支策略：沿用当前功能分支；不得自行推送 `main`
- 阶段标签前缀：`checkpoint/<feature-slug>/phase-N`
- 数据 / 外部状态回退约定：SQLite 变更先备份本地库；PostgreSQL 迁移必须附回退或前向修复方案；订阅扣费使用补偿流程
- 敏感信息规则：真实密码、令牌、私钥和带口令连接串一律不得进入 Git

## 总指挥施工

- 开发工具：家里用 Claude Code，公司用 Codex
- 角色模型覆盖：无，按 skill 对照表

- 端口分配：用户走查 5180 / 8790；子 agent 联调 5190 / 8795；子 agent 自测 8796
- 线上操作：总指挥直接完成云端部署与后台录入；应用商店上架资料由用户自己提交
- 先问用户的操作：默认四类，另加“向订阅用户群发通知”
- 工具权限约定：部署脚本已在全局规则放行

- 额度管理：不主动询问
- 汇报对象的沟通约定：中文、先讲结果再讲原因
- 多台电脑的仓库路径：只有一台开发机
